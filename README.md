# Лабораторная работа 6

Тема: введение в FastAPI.

Сделано приложение для работы с товарами: получение, создание и обновление. Есть проверка данных, настройки из `.env` и логирование.

## Запуск

Нужны Python и uv. В `.python-version` выбрана версия Python 3.14. Команды выполняются из папки проекта.

```powershell
uv sync --locked
Copy-Item .env.example .env
uv run uvicorn main:app --reload
```

Если `.env` уже настроен, копировать его заново не нужно.

- Приложение: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc

Проверка тестов:

```powershell
uv run pytest -q
```

## 1. Подготовка проекта

Проект подготовлен в папке `lab6`. Добавлен `.gitignore`, создано окружение через uv и установлены FastAPI и Uvicorn. Зависимости записаны в `pyproject.toml` и `uv.lock`.

В `main.py` добавлен маршрут `GET /`. Он возвращает:

```json
{"message": "Hello, FastAPI!"}
```

Проверены главная страница, `/docs` и `/redoc`. Все страницы открываются.

![Документация первого приложения](screenshots/01-docs.jpg)

## 2. Параметры пути и запроса

Добавлен `GET /items/{item_id}`. Параметр `item_id` должен быть целым числом, а `q` можно не указывать.

На этом этапе запрос `/items/42?q=test` вернул `{"item_id":42,"q":"test"}`. Без `q` возвращался `null`. Запрос выполнен через кнопку Try it out в Swagger.

![Проверка параметров в Swagger](screenshots/02-query.jpg)

## 3. Модель товара и POST

Pydantic добавлен как отдельная зависимость. Создана модель `Item` с полями `name`, `price` и необязательным `is_offer`.

Маршрут `POST /items/` принимает JSON и возвращает товар. В Swagger отправлен товар «Телефон» с ценой 199.99. Получен код 200 и те же данные.

![Создание товара](screenshots/03-post.jpg)

## 4. Отдельный роутер

Маршруты товаров перенесены в `app/routers/items.py`. Использован `APIRouter` с префиксом `/items` и тегом `items`. В папках `app` и `routers` есть `__init__.py`.

Роутер подключён в `main.py`. После переноса GET и POST проверены повторно: адреса и ответы сохранились.

![Маршруты в группе items](screenshots/04-router.jpg)

## 5. Настройки приложения

Установлен `pydantic-settings`. В `app/config.py` создан класс `Settings`. Из `.env` читаются `ADMIN_EMAIL` и `ITEMS_PER_PAGE`.

Добавлен `GET /info`. Проверка показала `items_per_page: 20`, то есть значение взялось из `.env`, а не из значения по умолчанию 10. Название приложения в документации тоже берётся из настроек.

Файл `.env` исключён из Git. В проект добавлен `.env.example` с примером настроек.

## 6. Ошибки и документация

Добавлен словарь `fake_db`. В нём изначально находится товар с ID 1, названием `Foo` и ценой 50.2. Для неизвестного ID возвращается 404 с сообщением `Item not found`.

У параметров и полей появились описания и примеры. ID должен быть не меньше 1, строка `q` ограничена 50 символами, цена должна быть больше нуля. Неверные данные дают 422. В документации указаны название, описание, версия 1.0.0 и контакт.

После этого этапа `/items/42` уже возвращает 404: товар 42 отсутствует в словаре. Для успешной проверки используется `/items/1?q=test`.

![Ошибка при запросе неизвестного товара](screenshots/06-not-found.jpg)

## 7. Обновление и уникальность имени

Добавлен `PUT /items/{item_id}`. Он полностью обновляет существующий товар. Для отсутствующего товара возвращается 404.

Проверена смена цены товара 1 на 75. Повторный GET вернул новую цену. Обновлять товар, сохраняя его собственное имя, разрешено.

![Успешное обновление товара](screenshots/07-update.jpg)

Имя проверяется при создании и обновлении. Регистр и пробелы по краям не учитываются: `Foo`, `foo` и ` FOO ` считаются одним именем. Если имя занято другим товаром, возвращается 409. Пустое имя и некорректная цена дают 422.

Для проверки создан второй товар `Bar`. Попытка переименовать товар 1 в `Bar` вернула 409. Старые данные товара сохранились.

![Ошибка при повторяющемся имени](screenshots/07-duplicate.jpg)

Начиная с этого этапа POST сохраняет товары в словаре, чтобы новые товары тоже участвовали в проверке уникальности. ID выдаётся автоматически. Адрес созданного товара возвращается в заголовке `Location`, например `/items/2`; тело ответа по-прежнему содержит поля модели `Item`.

Проверка имени и запись защищены блокировкой, чтобы два одновременных запроса не создали товары с одинаковыми именами.

## 8. Логирование

Использована стандартная библиотека `logging`. Настройка находится в `app/logging_config.py`.

В консоль и `logs/app.log` записываются метод запроса, путь, код ответа и время обработки. Отдельно записываются создание и обновление товара, отсутствие товара и повтор имени. Для обычных действий используется INFO, для ошибок клиента — WARNING. Необработанные ошибки записываются с traceback.

На скриншоте показан фрагмент настоящего лога после запросов с кодами 200, 404, 409 и 422. Файлы логов исключены из Git.

## Что нужно учитывать

Это учебное приложение. Товары хранятся в памяти одного процесса. После перезапуска остаётся только исходный товар `Foo`. Запускать приложение нужно с одним процессом Uvicorn. Параметр `q` возвращается в ответе для демонстрации query-параметра; отдельный поиск по названию не реализуется. `items_per_page` показан через `/info`, пагинация заданием не предусмотрена.
